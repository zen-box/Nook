# 同步、备份与换机

日常记录先写本机。S3 是用户可选的密文存储，不需要 Nook 账号或 Go 服务端；用户可选择实现相应 S3 契约的 AWS、R2、腾讯云、阿里云等服务，具体兼容性需按 Endpoint / Region / 寻址方式实测。

## 首次启用 S3

1. 为 Nook 准备独立桶或前缀。凭据应仅允许列举该前缀、读取 / 写入对应对象；App 当前不需要删除权限。
2. 设置 Endpoint（HTTPS）、Bucket、Region、Prefix 与寻址方式；填 Access Key / Secret Key，可选 Session Token。
3. 选择创建新加密资料库，单独保管生成的 `NOOK1.…` 恢复码并确认已保存，再连接同步。
4. 等待“同步成功”和最后成功时间。首次连接不会覆盖已经存在的 `library.json`。

凭据只赋予存储访问权，恢复码赋予内容解密权。两者不要和备份文件放在同一处。App 根密钥与连接凭据保存在本机 Keychain；AI API Key 不属于同步内容。

## 新设备恢复已有 S3

输入原来的 Endpoint / Bucket / Region / Prefix 和凭据，不选择创建，填入原恢复码，连接后同步。空设备不会用默认设置创建一个竞争版本。密码库搬回来的仍是密封资料，打开时需要其主密码；Face ID / Touch ID 快捷解锁在新手机重新启用。

丢失全部设备及恢复码后无法通过 S3 凭据恢复明文。当前没有托管找回服务。更改 Bucket / Prefix 不会移动旧对象；不可把新路径误认为原资料库。

## 没有 S3 时的扫码换机

1. 两台手机连接允许 Bonjour 的同一局域网。
2. 新手机进入设置 → 设备迁移 → 接收，显示二维码（10 分钟有效）。
3. 旧手机进入发送，扫码或手动粘贴配对码；允许相机 / 本地网络权限。
4. 对照两边六位验证码，两边均确认后开始传输。
5. 新手机完整接收并验证后，再确认替换本机资料；看到完成后检查内容。旧手机不会自动清空。

若旧手机配置 S3，可选择同时携带连接与恢复所需状态，它们仅经这条加密且受双端确认的会话传送。新端在数据提交时原子切换凭据指针，迁移成功后继续原资料库。AI API Key 不迁移。中断时保留旧手机，重新配对重试。

## 导出完整备份

设置 → 加密备份，准备恢复码并单独保存，生成并分享 `.nookbackup` 到安全位置。该文件包含记录、照片、录音、设置和密封密码库；备份恢复码与 S3 恢复码是不同密钥，虽然文本前缀相同，必须使用对应的那个。

恢复时选文件和对应备份恢复码，先完成验证，再确认替换。当前资料会被替换；若已经连接 S3，替换产生的变化会在后续同步传播。先给当前资料另做备份。旧 JSON 导出不能替代完整加密包。

## 并发、断网和历史

- 断网期间正常编辑；失败上传保留本地内容，恢复网络后重试。
- 同一条记录双端独立修改后保留冲突版本，在设置 → S3 同步中显式选择；另一份在冲突解决前不会被静默丢弃。
- 历史恢复先保存当前数据到云端，再替换本地。恢复后再次同步，将恢复动作传播给其他设备。
- 自动同步在 App 活跃时运行，变更防抖约 3 秒；后台挂起与强制退出不保证上传。卸载旧手机前打开 App，手动同步并核对成功时间，或做完整备份。
- 断开 S3 不会删除桶、历史或本地记录，也保留本机根密钥。当前没有远程撤销、轮换根密钥或自动清理云端历史功能。

## 当前实现的边界

同步使用整库不可变快照，附件先上传、快照最后提交。历史持续累积，适合当前个人规模；大库流量和处理开销需要后续增量优化。单个加密对象 / 备份帧上限 100 MiB，录音保存上限 90 MiB；暂不提供大文件分块续传。局域网迁移按块传输整个加密备份包，新手机预留足够临时空间。

加密认证能检查内容与对象上下文，无法阻止有桶删除权的第三方删除或整体回滚存储。因此应保留独立备份，并考虑存储厂商的版本 / 保留策略。当前测试包含模拟 HTTP S3 的两独立仓库合并、并发冲突、失败重试和密文检查；具体厂商与真实双手机迁移仍需实测。
