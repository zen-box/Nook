# 决策记录

规格书第 0 节要求：未定义的细节选最简单、可迁移的方案，并记在这里。每条写明决定、原因，以及以后怎么改。

## 工程与构建

| # | 决定 | 原因 / 以后怎么改 |
|---|---|---|
| D1 | 产品名 **Nook**；主 App 的 Bundle ID 为 `com.nook.personal`，测试 Target 分别为 `com.nook.personal.tests`、`com.nook.personal.uitests`。 | 按用户确认采用反向域名形式，标识独立于 GitHub 账号。若万能签重签时更换 ID，已安装的 App 会被系统视为另一个 App。 |
| D2 | 用 XcodeGen 2.46.0 从 `ios/project.yml` 生成工程，下载时校验 SHA-256；生成的 `Nook.xcodeproj` 不入库。 | Windows 上没有 Xcode，工程文件只能在云端生成；固定版本和校验值让每次构建一致。升级时同时改 `scripts/install-xcodegen.sh` 里的版本号和校验值。 |
| D3 | Codemagic 用 `mac_mini_m2`，Xcode 固定 `26.6`。 | 当前默认版本。Codemagic 不再提供这个版本时改成 `latest` 或新的版本号。 |
| D4 | 三个工作流：`ios-simulator-preview`（模拟器 `.app`，给 App Preview）、`ios-device-unsigned`（关闭签名的 `Nook-unsigned.ipa`，给万能签）、`ios-tests`（NookCore + App 单元/UI 测试）。 | 规格书 13.3：模拟器产物不能改包成真机 IPA，两条路径分开。CI 里不放任何证书或描述文件。 |
| D5 | Swift 6 语言模式，不开默认 MainActor 隔离；部署目标 iOS 17。 | 并发检查最严格，且不依赖较新的编译器默认值。界面状态类显式标 `@MainActor`。 |
| D6 | 底部 Tab 栏和各主页面标题是自绘的；详情页用系统导航栏。没有使用 iOS 26 的 Liquid Glass 接口。 | 参考图的悬浮白色 Tab 栏、选中态（首页深色圆、其他页浅蓝胶囊）系统 TabView 做不出来；不用新接口才能兼容 iOS 17。 |

## 数据

| # | 决定 | 原因 / 以后怎么改 |
|---|---|---|
| D7 | App 使用 GRDB 7.12.0 / SQLite，AppDatabase 负责迁移与事务，AppStore 保存界面快照；数据库写成功后才更新界面。示例数据仅在 Debug UI 测试载入。 | 普通记录与密码库分别存表。NookCore 保留可移植 Repository 协议与内存实现；App 通过专用数据库门面处理多表原子写入。 |
| D8 | 便签用 `category`（工作 / 旅行 / 生活 / 个人）代替 `folder_id`。 | 参考图只有分类筛选。P1 迁移时每个分类建一个文件夹，`category` 写入 `folder_id`。 |
| D9 | 全天日程：开始 = 首日本地 0 点，结束 = 末日次日 0 点（左闭右开）。没有时长的日程只算在开始那天。 | 跨天、跨时区计算都不用特殊处理。 |
| D10 | 金额存整数最小单位（`amount_minor`），始终非负，方向由 `type`（支出 / 收入 / 转账）决定；统计时其他币种直接排除，不做汇率换算。 | 避免浮点误差；汇率在 P2 账户功能里再定。 |
| D11 | 纪念日重复规则只有 `none` / `yearly`；2 月 29 日在平年按 2 月 28 日提醒。 | 规格书 6.2 的取值。农历留到以后加 `calendar_type`。 |
| D12 | 行程的阶段（未开始 / 进行中 / 已结束）实时计算，不存储。 | 不会出现过期状态。 |
| D13 | 本地密码库已接入秘密字段与加密持久化：Argon2id v1.3、XChaCha20-Poly1305，随机 256 位库密钥；主密码派生密钥只用于包裹库密钥。 | 使用 swift-sodium 0.11.0 提供的 libsodium C API，不自写密码算法；参数、格式、兼容迁移见 docs/local-vault.md。密封密码库进入外层 E2EE 备份 / S3，同步恢复码不能替代主密码。 |

## 格式

| # | 决定 | 原因 / 以后怎么改 |
|---|---|---|
| D14 | 记录 ID 用 UUIDv7。JSON 统一用 RFC 3339 UTC 时间（带毫秒）、键名排序、无填充 Base64URL；日期（不带时间）用 `YYYY-MM-DD`。 | 规格书 6.1、9。键名排序让导出文件可以直接 diff。 |
| D15 | 早期 `RecordEnvelope` 保留兼容测试，不用于当前 S3；现行协议为 `SyncDocument` 与加密快照，见 docs/api/README.md。 | 旧 Go API 文档已归档；更改现行格式必须兼容已有资料库。 |
| D16 | 旧 JSON 保留兼容；完整备份使用 `.nookbackup`，包含附件、设置与密封密码库，认证清单和文件逐帧加密。 | 完整备份的恢复码独立保管；恢复为替换并先验证。旧 JSON 的附件引用不能代替文件。 |

## 规则

| # | 决定 | 原因 / 以后怎么改 |
|---|---|---|
| D17 | 便签搜索：按空格拆词，每个词都要命中（AND）；不区分大小写和重音（`cafe` 能搜到 `café`）；范围是标题、正文、清单项和标签。排序：置顶优先，然后按更新时间倒序。 | 最常见的预期。 |
| D18 | 统计区间都是左闭右开。分类占比用最大余数法，保证合计 100%；金额相同时按分类声明顺序排。 | 结果确定，和输入顺序无关。 |
| D19 | “本周”对比上周同样的几天（周一到今天）；“本月”对比上月同样的天数，今天是月末时对比上月整月。 | 进行中的周期不和完整周期比，百分比才有意义。 |
| D20 | “即将开始”= 还没开始或正在进行的日程。 | 首页卡片在会议进行中也应该显示它。 |
| D21 | 参考图里“本周支出”的 Shopping 16% 和金额对不上，界面显示按真实金额算出的结果。 | 数字必须能自洽。 |

|---|---|---|

| D23 | 颜色、字号、间距、圆角集中在 `ios/Nook/DesignSystem`，所有颜色都有浅色和深色两套值。 | 规格书 3.2 的 Token，深色值是在同一色相上调暗。 |
| D24 | 头像、通知和设置均为本地功能：名称 / 外观 / 货币 / 预算 / 备份导入导出 / 密码库管理；UserNotifications 合并日程、任务、纪念日，调度最早 60 个请求；简单无限日 / 周规则用原生重复请求，其余滚动补排。 | 没有账号和远程推送。通知需要系统授权；重签后的权限与后台表现需真机验证。 |
| D25 | AppIcon 由 `logo.png` 裁出：去掉白边，取圆角以内最大的正方形，铺满 1024×1024、无透明通道（`scripts/make-app-icon.py`）。 | iOS 会自己加圆角；原图带白边和圆角，直接用会出现白色边框。 |

| D28 | 密码库正式显示加密记录；后台锁定、非活跃快照遮罩，锁定后清空内存条目与编辑草稿。快捷解锁使用设备专属 Keychain 项的 userPresence 访问控制，读取密钥时由系统认证。 | 主密码路径独立于 Keychain，可在重签导致设备密钥副本失效后解锁。秘密复制仅限本机，90 秒过期；系统 API 与真机行为仍需云端 / 设备验收。 |


## v4：离线工具、S3 与事务助手

| # | 决定 | 原因 / 演进 |
|---|---|---|
| D29 | 当前客户端不依赖 Go 服务端或 Nook 账号，直接接用户 S3。 | 个人资料的控制权与运维成本优先；Go 历史骨架保留。 |
| D30 | S3 使用随机 256 位根密钥、HKDF-SHA256 / AES-GCM 上下文加密，与本地 Argon2id / XChaCha 密码库分层。 | CryptoKit 原生实现外层；不改写既有密码库格式。用户须分别保管对应恢复码与密码库主密码。 |
| D31 | 不可变附件和快照、向量时钟、多头冲突、显式选版，保留墓碑和历史。 | 不以墙钟覆盖并发编辑；先保证正确性，再做增量 / 安全回收。当前对象上限 100 MiB。 |
| D32 | 设备迁移双端核对六位码，X25519 临时会话、方向 / 序号认证，完整暂存后确认导入。 | 无 S3 也可换机；可选择携带 S3 凭据，API Key / 快捷解锁副本排除。 |
| D33 | Agent 只获得六种普通记录能力，搜索 / 追问 / 草稿，用户确认后事务写入、幂等和可撤销。 | 防止模型捏造已保存状态、重复执行、碰触密码库及基础设施秘密。 |
| D34 | 直接适配四种 AI 协议，不运行托管 AI 代理，Key 放本机 Keychain。 | 用户自配服务；模型列表支持搜索、手填与分页，视觉 / 工具能力需匹配模型。 |
| D35 | 语音只用本机 Speech，连续便签中保存 AAC 录音；不支持本机识别时允许手输。 | 避免未经选择上传音频；权限按需申请。 |
| D36 | 小组件独立扩展，共享裁剪摘要，详细标题默认关闭，App Group `group.com.nook.personal`。 | 降低锁屏 / 桌面泄露；重签必须保留对应 entitlement，缺失时报告不可用。 |
| D37 | GitHub Actions 先跑核心和原生单元 / UI 测试，再构建未签名 Release IPA并保存诊断与截图。 | 完整 iOS 编译不能被 Windows parse / 核心测试替代；Codemagic 路径继续保留。 |
| D38 | 交通表单归“行程”；底层使用关联定时日程，并与行程一起事务提交。Agent 可用 `trip.journey` 同时生成两者。 | 不复制日历 / 通知数据，不要求模型猜测新行程 UUID；兼容既有交通记录。 |
| D39 | 底栏中间是独立 Nook 按钮，五个模块入口保留；英文与简体中文显式打包，通过 iOS 应用语言切换。 | 事务助手保持就近入口，语言按系统机制一致作用于文字和扩展。 |
| D40 | AI 设置测试实际推理接口，不发送业务记录或注册工具，显示耗时与失败原因。 | 模型列表能获取不等于该模型能推理；连接测试成功也不承诺模型具备 Agent 工具能力。 |
| D41 | 小组件以日程 / 行程 / 便签标题 / 纪念日为主要内容，App 与扩展复用布局，分别诊断权限、无数据、读取失败。 | 可添加小组件不代表重签拥有 App Groups；预览和共享状态用于定位，不绕过系统权限。 |
